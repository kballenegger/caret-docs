Bring your own backend

Your keyboard, your agent, your machine.

Caret is a compose surface for iOS: speak or type an intent at the cursor, preview, insert a finished message. Everything it does, it does by calling an HTTP API you configure. These pages document that API and nothing else — implement it and the keyboard runs on your agent.

Implement the Caret APIcaret/v1

One page with every request and response shape, in the order you would build them: health and capabilities, Ask, spoken input over dictation sessions, Imagine, the error envelope, and the conformance checker that tells you when you are done.

The three surfaces

SurfaceWhat happensEndpoint
Ask An instruction — typed or spoken — becomes one insert-ready message. Always previewed before it goes into the text field. /v1/draft
Dictate Speech becomes polished, insert-ready text. Audio is uploaded in small chunks as it is spoken, each verified by SHA-256. /v1/dictation/*
Imagine A typed or spoken prompt becomes an image, delivered through the pasteboard. /v1/imagine

Only Ask and health are required. A text-only backend is a complete backend — say so in capabilities and Caret hides the rest.

One input model

Ask and Imagine accept typed text or spoken audio through the same field. Audio is not a second protocol: a spoken Ask opens an ordinary dictation session, uploads ordinary chunks, and then hands the session id to /v1/draft instead of to the transcript endpoint. 

{"input": {"type": "text",  "text": "tell Sam I'm running late"}}

{"input": {"type": "audio", "session_id": "sess_9f2c",
           "client_chunk_count": 4, "client_total_duration_ms": 11200}}

If you have implemented dictation, you have already implemented most of spoken Ask. A session carries exactly one terminal result, so whichever surface consumes it owns it.

Design principles

  • No privileged server. The keyboard talks to the base URL and API key you enter in the app. Any server that implements caret/v1 works.
  • Capabilities are honest. Health declares what you actually support, per surface and per input mode. The keyboard hides what you have not enabled rather than failing in the user's hands.
  • Stable error envelope. Every non-2xx response is {"error": {"code", "message", "retryable"}, "request_id"} with an append-only code list. Clients act on retryable when they meet an unknown code.
  • Idempotency everywhere. Mutating requests carry a client-generated client_request_id; replays return the original result and never re-run work.
  • Additive evolution. Unknown JSON fields are ignored on both sides. Breaking changes require a new path version (/v2).

Start in two minutes

The reference backend is one Python package with no dependencies. Run it, paste the URL and key into Caret, and your keyboard is live. 

cd reference-backend
export CARET_API_KEYS="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')"
python3 -m caret_backend --port 8787

The implementation guide covers the rest, and the machine-readable contract is at openapi.yaml.
