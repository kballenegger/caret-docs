connect · claude code

Claude Code behind your keyboard.

The reference backend runs one claude -p call per draft — print mode, read-only plan mode, nothing persisted — and hands the answer to Caret. Local OpenWhisper takes dictation on the same backend — the one capability every Caret backend must serve.

Status: tested

This Ask preset was verified end to end against a real Claude Code install: a live draft came back through the backend, idempotent replay included. The exact command per draft is claude -p --permission-mode plan --no-session-persistence "<prompt>" — every flag is stock, documented CLI syntax.

Plugin install

Claude Code has a documented plugin system, so this integration is also packaged as a plugin. Install it and ask Claude Code to "connect Caret" — the plugin's skill runs this runbook for you: 

claude plugin marketplace add kballenegger/caret-docs
claude plugin install caret-connect@caret-docs

What you need

  • The claude CLI installed and signed in on the machine that will run the backend (claude --version works).
  • Python 3.10+ (preinstalled on macOS and every mainstream Linux).
  • An STT adapter — required. OpenWhisper (brew install openai-whisper) is the default and keeps audio on the machine; CARET_STT_HTTP_URL or CARET_STT_COMMAND are the alternatives. With none of them, the backend is not_ready and --check fails: dictation is mandatory.
  • Tailscale on that machine and your iPhone, or a domain pointed at your VPS for public HTTPS.

1 · Get and configure the backend

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

export CARET_AGENT=claude-code
python3 -c 'import secrets;print(secrets.token_urlsafe(32))'  # generate a key — copy the output
export CARET_API_KEYS=paste-the-key-here                      # paste this into Caret later

python3 -m caret_backend --check
# config ok: ready   (agent=claude-code stt=openwhisper …)
# without an STT adapter this fails instead: NOT READY — no_stt_adapter

Want a specific model, or plan mode is not restrictive enough for your taste? Override the command rather than the code — substitution is argv-level, never a shell: 

# pin a fast model for drafting
export CARET_AGENT_COMMAND='claude -p --permission-mode plan --no-session-persistence --model haiku {prompt}'

The backend refuses any command containing a permission-bypass flag (--dangerously-skip-permissions and friends) — that refusal is a startup error, by design.

2 · Run it and smoke-test locally

python3 -m caret_backend --port 8787 &

curl -s localhost:8787/v2/health | python3 -m json.tool
curl -s -X POST localhost:8787/v2/ask \
  -H "Authorization: Bearer $CARET_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

Health's adapters block names what resolved ("agent": "claude-code", and "stt": "openwhisper" when dictation is on). First draft takes a few seconds (a full model call). If it fails, the error message carries the CLI's stderr tail — run the claude -p command by hand as the same user to see the whole story.

Dictation — mandatory

STT is the backend's own adapter lane — Claude Code plays no part in transcription. With OpenWhisper on PATH, dictation and spoken Ask are on: speech is transcribed locally first, and only the resulting text reaches claude -p. CARET_STT_MODEL picks the model (turbo default). See the STT section of the Connect overview for hosted and custom STT options.

This is not optional. With no STT adapter resolved, health reports "status": "not_ready" with the no_stt_adapter blocker, --check exits non-zero, and the connection QR refuses to generate — a backend that cannot take speech is not a Caret backend, however well claude -p drafts.

3a · Local Mac

Keep the backend on loopback and let Tailscale provide the private HTTPS URL: 

tailscale serve --bg 8787
# https://your-mac.your-tailnet.ts.net  ← this is the URL for Caret

Your iPhone must be on the same tailnet. Nothing is exposed publicly, and the certificate is handled for you. To keep the backend running across logins, wrap the exports and the python3 invocation in a LaunchAgent or just a tmux session — it is a single foreground process and survives being supervised by anything.

3b · VPS or hosted box

Same backend, same config, on the box where claude is signed in. Two transport options:

Tailnet (no open ports): exactly as on the Mac — tailscale serve --bg 8787.

Public HTTPS with Caddy:

# /etc/caddy/Caddyfile
caret.yourdomain.com {
    reverse_proxy 127.0.0.1:8787
}

Caddy fetches and renews the certificate automatically. The backend stays bound to 127.0.0.1; only the proxy is reachable, and the bearer key is the lock. Run the backend as a dedicated low-privilege user (useradd -m caret, sign claude in as that user) so a drafting call can never see more than that account does.

4 · Pair with Caret

Scan a code, or type two strings. The scan is one command:

python3 -m caret_backend --qr --url https://your-mac.your-tailnet.ts.net

That prints a caret-connect:v1 symbol carrying the base URL and the key; --save ~/caret-connect.png writes an owner-only PNG instead. It refuses while any readiness blocker stands. The code is the credential — anyone who scans it can use this backend until you rotate CARET_API_KEYS. Format and warnings: the connection QR.

Or by hand:

  1. Caret settings → your backend URL (https://your-mac.your-tailnet.ts.net or https://caret.yourdomain.com).
  2. Paste the API key you generated.
  3. The app runs the health check and shows what it found — dictation always, Ask when an agent resolved, Imagine only if you configured an image command.

Troubleshooting

SymptomFix
503 internal_error: claude-code command not found The backend's user cannot see the CLI. Install it for that user, or put its location on PATH in the same environment that launches the backend.
503 internal_error: claude-code exited 1: … Usually authentication — run claude -p "say ok" as the backend's user; sign in if prompted.
504 ask_timeout Model slower than the 90 s budget. Pin a faster model with CARET_AGENT_COMMAND (above) or raise CARET_AGENT_TIMEOUT_S.
Health reachable, drafts 401 Key in the app ≠ CARET_API_KEYS. Health's auth.valid tells you before a draft ever runs.
Health says "status": "not_ready", or no microphone in the keyboard No STT resolved, so this is not yet a valid Caret backend. Install OpenWhisper and restart, then check adapters.stt and readiness in health.

General transport and pairing problems are covered on the Connect overview.
