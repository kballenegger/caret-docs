connect · codex

Codex behind your keyboard.

The reference backend runs one codex exec per draft in a read-only sandbox with an ephemeral session, captures the final message cleanly, and hands it to Caret. Local OpenWhisper takes dictation on the same backend — the one capability every Caret backend must serve.

Status: tested

This Ask preset was verified end to end against a real Codex install: a live draft came back through the backend. The exact command per draft is codex exec --sandbox read-only --skip-git-repo-check --ephemeral --output-last-message <file> "<prompt>" — stock, documented CLI syntax throughout. Speech-to-text does not go through Codex — its non-interactive interface is text-only — so dictation uses the backend's own STT lane (OpenWhisper by default).

One mechanical detail worth knowing: Codex prints an event log on stdout, not the answer. The backend therefore uses the documented --output-last-message flag to have the final message written to a temp file it reads and deletes — you get the draft, never the log.

Codex's own plugin command installs only from configured marketplace snapshots and documents no third-party authoring path, so no Codex plugin is shipped — the CARET_AGENT=codex preset is the supported integration (see the decision matrix).

What you need

  • The codex CLI installed and authenticated on the machine that will run the backend (an API-key environment or codex login — whatever your install already uses).
  • Python 3.10+.
  • An STT adapter — required. OpenWhisper (brew install openai-whisper) is the default and keeps audio local; CARET_STT_HTTP_URL or CARET_STT_COMMAND are the alternatives. With none of them the backend is not_ready and --check fails: dictation is mandatory.
  • Tailscale on that machine and your iPhone, or a domain for public HTTPS on a VPS.

1 · Get and configure the backend

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

export CARET_AGENT=codex
python3 -c 'import secrets;print(secrets.token_urlsafe(32))'  # generate a key — copy the output
export CARET_API_KEYS=paste-the-key-here                      # paste this into Caret later

python3 -m caret_backend --check

To pin a model, extend the documented command line, keeping the safety flags:

export CARET_AGENT_COMMAND='codex exec --sandbox read-only --skip-git-repo-check --ephemeral --output-last-message {out} -m gpt-5.2 {prompt}'

{out} is the answer-file path the backend substitutes; {prompt} is the framed drafting prompt. Commands containing --dangerously-bypass-approvals-and-sandbox or danger-full-access are refused at startup.

2 · Run it and smoke-test locally

python3 -m caret_backend --port 8787 &

curl -s localhost:8787/v1/health | python3 -m json.tool
curl -s -X POST localhost:8787/v1/draft \
  -H "Authorization: Bearer $CARET_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

Health's routes block shows how each surface resolved: Ask and cleanup through codex, dictation through openwhisper, Imagine off unless you configured an image command. readiness.ready must be true.

Dictation — mandatory

STT does not go through Codex — speech is transcribed by the backend's own STT adapter first (local OpenWhisper by default), then the transcript is cleaned up through Codex as a constrained text-only request. See the STT section of the Connect overview.

And it is required. With no STT adapter resolved, health reports "status": "not_ready" with the no_stt_adapter blocker, --check exits non-zero, and the connection QR refuses to generate.

3a · Local Mac

tailscale serve --bg 8787
# https://your-mac.your-tailnet.ts.net  ← this is the URL for Caret

Private HTTPS over your tailnet, nothing public, certificates handled. Supervise the backend with a LaunchAgent or a tmux session if you want it up across reboots.

3b · VPS or hosted box

Tailnet (no open ports): tailscale serve --bg 8787, as above.

Public HTTPS with Caddy:

# /etc/caddy/Caddyfile
caret.yourdomain.com {
    reverse_proxy 127.0.0.1:8787
}

The backend stays on loopback; Caddy terminates TLS with automatic Let's Encrypt certificates. Run backend and CLI as a dedicated low-privilege user (useradd -m caret) and authenticate Codex as that user — the read-only sandbox then applies on top of an account that has nothing interesting to read.

4 · Pair with Caret

Scan a code, or type two strings. The scan is one command:

python3 -m caret_backend --qr --url https://your-backend.example

That prints a caret-connect:v1 symbol carrying the base URL and the key; --save ~/caret-connect.png writes an owner-only PNG instead. It refuses while any readiness blocker stands. The code is the credential — anyone who scans it can use this backend until you rotate CARET_API_KEYS. Format and warnings: the connection QR.

Or by hand:

  1. Caret settings → your backend URL.
  2. Paste the API key.
  3. The health check reports what actually resolved; Caret hides any surface that is off.

Troubleshooting

SymptomFix
503 internal_error: codex command not found Install the CLI for the backend's user, or fix PATH in the environment that launches the backend.
503 internal_error: codex exited 1: … Usually authentication or provider config. Run codex exec --sandbox read-only --skip-git-repo-check "say ok" by hand as the backend's user.
503 internal_error: codex returned an empty answer The run produced no final message — the same manual command shows why.
504 draft_timeout Pin a faster model (above) or raise CARET_AGENT_TIMEOUT_S.
Health says "status": "not_ready", or no microphone in the keyboard No STT resolved, so this is not yet a valid Caret backend. Install OpenWhisper and restart, then check routes.dictation and readiness in health.

General transport and pairing problems are covered on the Connect overview.
