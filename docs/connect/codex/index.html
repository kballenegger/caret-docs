connect · codex

Codex behind your keyboard.

The bridge runs one codex exec per draft in a read-only sandbox with an ephemeral session, captures the final message cleanly, and hands it to Caret.

Status: tested

This preset was verified end to end against a real Codex install: a live draft came back through the bridge. The exact command per draft is codex exec --sandbox read-only --skip-git-repo-check --ephemeral --output-last-message <file> "<prompt>" — stock, documented CLI syntax throughout.

One mechanical detail worth knowing: Codex prints an event log on stdout, not the answer. The bridge therefore uses the documented --output-last-message flag to have the final message written to a temp file it reads and deletes — you get the draft, never the log.

What you need

  • The codex CLI installed and authenticated on the machine that will run the bridge (an API-key environment or codex login — whatever your install already uses).
  • Python 3.10+.
  • Tailscale on that machine and your iPhone, or a domain for public HTTPS on a VPS.

1 · Get and configure the bridge

curl -fsSLO https://docs.typewithcaret.com/agent-bridge/caret_agent_bridge.py

export CARET_BRIDGE_BACKEND=codex
export CARET_BRIDGE_API_KEYS="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')"
echo "$CARET_BRIDGE_API_KEYS"               # paste this into Caret later

python3 caret_agent_bridge.py --check

To pin a model, extend the documented command line, keeping the safety flags:

export CARET_BRIDGE_COMMAND='codex exec --sandbox read-only --skip-git-repo-check --ephemeral --output-last-message {out} -m gpt-5.2 {prompt}'

{out} is the answer-file path the bridge substitutes; {prompt} is the framed drafting prompt. Commands containing --dangerously-bypass-approvals-and-sandbox or danger-full-access are refused at startup.

2 · Run it and smoke-test locally

python3 caret_agent_bridge.py --port 8790 &

curl -s localhost:8790/v1/health | python3 -m json.tool
curl -s -X POST localhost:8790/v1/draft \
  -H "Authorization: Bearer $CARET_BRIDGE_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

3a · Local Mac

tailscale serve --bg 8790
# https://your-mac.your-tailnet.ts.net  ← this is the URL for Caret

Private HTTPS over your tailnet, nothing public, certificates handled. Supervise the bridge with a LaunchAgent or a tmux session if you want it up across reboots.

3b · VPS or hosted box

Tailnet (no open ports): tailscale serve --bg 8790, as above.

Public HTTPS with Caddy:

# /etc/caddy/Caddyfile
caret.yourdomain.com {
    reverse_proxy 127.0.0.1:8790
}

The bridge stays on loopback; Caddy terminates TLS with automatic Let's Encrypt certificates. Run bridge and CLI as a dedicated low-privilege user (useradd -m caret-bridge) and authenticate Codex as that user — the read-only sandbox then applies on top of an account that has nothing interesting to read.

4 · Pair with Caret

  1. Caret settings → your bridge URL.
  2. Paste the API key.
  3. The health check confirms text-only Ask — no microphone will be offered, which is honest, because this bridge cannot transcribe.

Troubleshooting

SymptomFix
configuration error: 'codex' not found on PATH Install the CLI for the bridge's user, or fix PATH in the environment that launches the bridge.
503 internal_error: codex exited 1: … Usually authentication or provider config. Run codex exec --sandbox read-only --skip-git-repo-check "say ok" by hand as the bridge's user.
503 internal_error: codex returned an empty answer The run produced no final message — the same manual command shows why.
504 draft_timeout Pin a faster model (above) or raise CARET_BRIDGE_TIMEOUT_S.

General transport and pairing problems are covered on the Connect overview.
