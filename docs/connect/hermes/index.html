connect · hermes

Hermes behind your keyboard.

The bridge runs one hermes chat -q "<prompt>" -Q per draft — the stock single-query, quiet-mode invocation — and hands stdout to Caret.

Status: bridge-supported

The preset uses only stock, documented Hermes CLI syntax (-q/--query single-query non-interactive mode, -Q/--quiet quiet mode for programmatic use), and the bridge's construction of that command is covered by the hermetic test suite. The suite does not execute a real Hermes install, so drafts through your particular Hermes configuration are yours to smoke-test — step 2 does exactly that. The bridge patches no Hermes source and reads or writes no Hermes config.

What you need

  • The hermes CLI installed and configured on the machine that will run the bridge (hermes chat -q "say ok" -Q answers).
  • Python 3.10+.
  • Tailscale on that machine and your iPhone, or a domain for public HTTPS on a VPS.

1 · Get and configure the bridge

curl -fsSLO https://docs.typewithcaret.com/agent-bridge/caret_agent_bridge.py

export CARET_BRIDGE_BACKEND=hermes
export CARET_BRIDGE_API_KEYS="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')"
echo "$CARET_BRIDGE_API_KEYS"               # paste this into Caret later

python3 caret_agent_bridge.py --check

Narrow what a draft can reach — recommended, not optional

Be clear-eyed about the default: a hermes chat call inherits whatever toolsets your Hermes configuration enables. The bridge never widens that — but it cannot narrow it silently either, because overriding your configuration behind your back would be its own kind of surprise. The drafting prompt says "write the message, take no action", and a prompt is an instruction, not an enforcement boundary.

So narrow it yourself, with the documented flag, in one line: 

# restrict drafting calls to the toolsets you name (hermes tools list shows yours)
export CARET_BRIDGE_COMMAND='hermes chat -q "{prompt}" -Q -t clarify'

# and/or pin model and provider — documented hermes chat options
export CARET_BRIDGE_COMMAND='hermes chat -q "{prompt}" -Q -t clarify -m gpt-5.2 --provider openai'

Better still, run the bridge as a dedicated low-privilege user with its own minimal Hermes profile — then the account boundary does what no flag or prompt can.

2 · Run it and smoke-test locally

python3 caret_agent_bridge.py --port 8790 &

curl -s localhost:8790/v1/health | python3 -m json.tool
curl -s -X POST localhost:8790/v1/draft \
  -H "Authorization: Bearer $CARET_BRIDGE_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

This smoke test is the step that turns "bridge-supported" into "works on my machine, verified" — for your install, which is the one that matters.

3a · Local Mac

tailscale serve --bg 8790
# https://your-mac.your-tailnet.ts.net  ← this is the URL for Caret

Private HTTPS over your tailnet; nothing public; certificates handled. Supervise with a LaunchAgent or tmux to survive reboots.

3b · VPS or hosted box

Tailnet (no open ports): tailscale serve --bg 8790, as above.

Public HTTPS with Caddy:

# /etc/caddy/Caddyfile
caret.yourdomain.com {
    reverse_proxy 127.0.0.1:8790
}

Bridge on loopback, proxy terminates TLS, bearer key is the lock. On a shared or long-lived box, the dedicated-user recommendation above stops being a recommendation and becomes the setup.

4 · Pair with Caret

  1. Caret settings → your bridge URL.
  2. Paste the API key.
  3. The health check reports text-only Ask; Caret hides dictation and Imagine.

Troubleshooting

SymptomFix
configuration error: 'hermes' not found on PATH The bridge's user cannot see the CLI — install or PATH-fix for that user.
503 internal_error: hermes exited N: … Run hermes chat -q "say ok" -Q as the bridge's user; the stderr tail in the bridge's error is the same story, truncated.
Drafts contain banner or spinner text Your command override lost -Q. Quiet mode is what keeps stdout answer-only.
504 draft_timeout Pin a faster model (above) or raise CARET_BRIDGE_TIMEOUT_S.

General transport and pairing problems are covered on the Connect overview.
