connect · hermes

Hermes behind your keyboard.

The reference backend runs one hermes chat -q "<prompt>" -Q per draft — the stock single-query, quiet-mode invocation — and hands stdout to Caret. Local OpenWhisper takes dictation on the same backend — the one capability every Caret backend must serve.

Status: backend-supported

The preset uses only stock, documented Hermes CLI syntax (-q/--query single-query non-interactive mode, -Q/--quiet quiet mode for programmatic use), and the backend's construction of that command is covered by the hermetic test suite. The suite does not execute a real Hermes install, so drafts through your particular Hermes configuration are yours to smoke-test — step 2 does exactly that. The backend patches no Hermes source and reads or writes no Hermes config. Speech-to-text does not go through Hermes: no documented stable CLI contract for transcription exists, so nothing is claimed — dictation uses the backend's own STT lane (OpenWhisper by default).

Skill install

Hermes has a documented skills system, so this integration is also packaged as an installable skill. Install it and ask Hermes to "connect Caret" — the skill runs this runbook for you: 

hermes skills install https://raw.githubusercontent.com/kballenegger/caret-docs/main/integrations/hermes/caret-connect/SKILL.md

What you need

  • The hermes CLI installed and configured on the machine that will run the backend (hermes chat -q "say ok" -Q answers).
  • Python 3.10+.
  • An STT adapter — required. OpenWhisper (brew install openai-whisper) is the default and keeps audio local; CARET_STT_HTTP_URL or CARET_STT_COMMAND are the alternatives. With none of them the backend is not_ready and --check fails: dictation is mandatory.
  • Tailscale on that machine and your iPhone, or a domain for public HTTPS on a VPS.

1 · Get and configure the backend

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

export CARET_AGENT=hermes
python3 -c 'import secrets;print(secrets.token_urlsafe(32))'  # generate a key — copy the output
export CARET_API_KEYS=paste-the-key-here                      # paste this into Caret later

python3 -m caret_backend --check

Narrow what a draft can reach — recommended, not optional

Be clear-eyed about the default: a hermes chat call inherits whatever toolsets your Hermes configuration enables. The backend never widens that — and refuses permission-bypass flags outright — but it cannot narrow your configuration silently either, because overriding it behind your back would be its own kind of surprise. The drafting prompt and the cleanup prompt both say "take no action", and a prompt is an instruction, not an enforcement boundary.

So narrow it yourself, with the documented flag, in one line: 

# restrict drafting calls to the toolsets you name (hermes tools list shows yours)
export CARET_AGENT_COMMAND='hermes chat -q "{prompt}" -Q -t clarify'

# and/or pin model and provider — documented hermes chat options
export CARET_AGENT_COMMAND='hermes chat -q "{prompt}" -Q -t clarify -m gpt-5.2 --provider openai'

Better still, run the backend as a dedicated low-privilege user with its own minimal Hermes profile — then the account boundary does what no flag or prompt can.

2 · Run it and smoke-test locally

python3 -m caret_backend --port 8787 &

curl -s localhost:8787/v1/health | python3 -m json.tool
curl -s -X POST localhost:8787/v1/draft \
  -H "Authorization: Bearer $CARET_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

This smoke test is the step that turns "backend-supported" into "works on my machine, verified" — for your install, which is the one that matters. Health's routes block shows how each surface resolved: Ask and cleanup through hermes, dictation through openwhisper, Imagine off unless you configured an image command. readiness.ready must be true.

Dictation — mandatory

STT does not go through Hermes — speech is transcribed by the backend's own STT adapter first (local OpenWhisper by default), then the transcript is cleaned up through Hermes as a constrained text-only request. See the STT section of the Connect overview.

And it is required. With no STT adapter resolved, health reports "status": "not_ready" with the no_stt_adapter blocker, --check exits non-zero, and the connection QR refuses to generate.

3a · Local Mac

tailscale serve --bg 8787
# https://your-mac.your-tailnet.ts.net  ← this is the URL for Caret

Private HTTPS over your tailnet; nothing public; certificates handled. Supervise with a LaunchAgent or tmux to survive reboots.

3b · VPS or hosted box

Tailnet (no open ports): tailscale serve --bg 8787, as above.

Public HTTPS with Caddy:

# /etc/caddy/Caddyfile
caret.yourdomain.com {
    reverse_proxy 127.0.0.1:8787
}

Backend on loopback, proxy terminates TLS, bearer key is the lock. On a shared or long-lived box, the dedicated-user recommendation above stops being a recommendation and becomes the setup.

4 · Pair with Caret

Scan a code, or type two strings. The scan is one command:

python3 -m caret_backend --qr --url https://your-backend.example

That prints a caret-connect:v1 symbol carrying the base URL and the key; --save ~/caret-connect.png writes an owner-only PNG instead. It refuses while any readiness blocker stands. The code is the credential — anyone who scans it can use this backend until you rotate CARET_API_KEYS. Format and warnings: the connection QR.

Or by hand:

  1. Caret settings → your backend URL.
  2. Paste the API key.
  3. The health check reports what actually resolved; Caret hides any surface that is off.

Troubleshooting

SymptomFix
503 internal_error: hermes command not found The backend's user cannot see the CLI — install or PATH-fix for that user.
503 internal_error: hermes exited N: … Run hermes chat -q "say ok" -Q as the backend's user; the stderr tail in the backend's error is the same story, truncated.
Drafts contain banner or spinner text Your command override lost -Q. Quiet mode is what keeps stdout answer-only.
504 draft_timeout Pin a faster model (above) or raise CARET_AGENT_TIMEOUT_S.
Health says "status": "not_ready", or no microphone in the keyboard No STT resolved, so this is not yet a valid Caret backend. Install OpenWhisper and restart, then check routes.dictation and readiness in health.

General transport and pairing problems are covered on the Connect overview.
