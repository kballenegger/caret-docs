connect · openclaw

OpenClaw behind your keyboard.

The reference backend has an openclaw preset, but it ships no default command for it — because none could be verified, and a guessed command line published as documentation would be a support claim we cannot back.

Status: not yet verified

OpenClaw was not available on the machine this backend was developed and tested on, so no invocation has been checked against a real install — and no plugin, STT, or image capability is claimed either. Selecting CARET_AGENT=openclaw without an explicit command is a startup error by design. Everything below is the honest path from "unverified" to "works on my machine, verified" — it takes about ten minutes and one model call.

What the backend needs from OpenClaw

The same thing it needs from every CLI runtime — one non-interactive command that:

  • reads a prompt, either as an argument (where you write {prompt}) or on stdin (if the template has no {prompt});
  • prints the reply — and nothing else — on stdout;
  • exits 0 on success, non-zero on failure.

If your OpenClaw install has a documented one-shot / non-interactive chat mode, use it directly. If its output mixes logs with the answer, wrap it in a five-line script that extracts the reply and prints only that, and point the backend at the wrapper. Prefer whatever flags your install documents for running without tools or actions — the drafting call should be text-in, text-out.

1 · Configure with an explicit command

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

export CARET_AGENT=openclaw
# YOUR verified invocation — this example shape is illustrative, not documentation:
export CARET_AGENT_COMMAND='openclaw-draft-wrapper {prompt}'
export CARET_API_KEYS="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')"

python3 -m caret_backend --check

Substitution is argv-level — no shell ever sees the prompt. Commands containing known permission-bypass flags are refused at startup.

2 · Verify it yourself

First the command alone, then the chain:

# 1. does the command behave? (run as the backend's user)
echo ok | openclaw-draft-wrapper "reply with exactly: ok"

# 2. does the chain draft?
python3 -m caret_backend --port 8787 &
curl -s -X POST localhost:8787/v1/draft \
  -H "Authorization: Bearer $CARET_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

A clean draft here means your integration is verified — for your install, which is the one that matters. If you land on a stable, stock-syntax OpenClaw invocation, please open an issue on the public caret-docs repository with the exact command line; verified submissions are how this page's label changes.

Dictation

STT does not go through OpenClaw — even if your install has voice features, no stable transcription contract could be verified, so nothing is routed through it. Dictation uses the backend's own STT lane: local OpenWhisper by default when installed, or the adapter you configure. See the STT section of the Connect overview.

3 · Host modes

Identical to every other backend once the command works. Local Mac: tailscale serve --bg 8787 for a private tailnet HTTPS URL. VPS / hosted box: the same tailnet command, or public HTTPS via a Caddy site block (reverse_proxy 127.0.0.1:8787) with the backend kept on loopback and run as a dedicated low-privilege user with a minimal OpenClaw profile. Details and trade-offs: the Connect overview.

4 · Pair with Caret

URL + key in Caret settings; the health check shows "agent": "openclaw" in the adapters block and reports what actually resolved per surface in routes.

Troubleshooting

SymptomFix
configuration error: the openclaw preset is not yet verified… Working as intended — set CARET_AGENT_COMMAND to your verified invocation.
503 internal_error: openclaw exited N: … The command failed; its stderr tail is in the message. Re-run it by hand as the backend's user.
Drafts contain log lines or banners Your command's stdout is not answer-only — add the quiet flag your install documents, or wrap and filter.
503 internal_error: openclaw returned an empty answer The command printed nothing — usually a wrapper writing to the wrong stream.
