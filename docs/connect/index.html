Connect your agent · the primary path

The agent you already run, behind your keyboard.

If you already run an agent — on your Mac, on a VPS, or hosted somewhere — the Caret reference backend puts it behind your keyboard. One unified backend, a config switch per capability: local OpenWhisper takes dictation — the one capability every Caret backend must serve — your agent answers Ask, and nothing sits in the middle of your typing.

To be precise about what this is: Caret does not integrate with any agent directly. Caret talks to one HTTP contract (caret/v1), and the reference backend is the canonical public implementation of it, with a pluggable adapter per capability. Its source of truth is the public kballenegger/caret-docs repository, where you can read it, its tests, and its docs. The tables below say honestly, per runtime, how far support has been verified.

The backend in one minutestdlib python

Standard-library Python you can read end to end (browse the source on GitHub). Clone it, pick your agent, generate a key: 

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

export CARET_AGENT=claude-code              # hermes | codex | grokbot | openclaw | custom-http | off
python3 -c 'import secrets;print(secrets.token_urlsafe(32))'  # generate a key — copy the output
export CARET_API_KEYS=paste-the-key-here                      # this goes into the Caret app

python3 -m caret_backend --check            # validate configuration and readiness
python3 -m caret_backend --port 8787        # run

--check is a readiness gate, not a formality: it fails if no STT adapter resolved, because dictation is mandatory. Then put TLS in front (below) and either paste the URL and key into Caret's settings or scan the connection QR.

Compatibility matrix

Three labels, used strictly:

  • Tested — the preset was run end to end against a real install of the runtime: a live draft came back through the backend.
  • Backend-supported — the backend's side of the boundary is fully covered by the hermetic test suite, and the preset uses only the runtime's stock documented syntax — but the suite does not execute the real runtime.
  • Not yet verified — no stable interface could be checked, so the backend ships no default and refuses the preset until you configure it explicitly. Not a support claim.

Capabilities are routed, not assumed

The backend serves four surfaces, and each one routes to whatever actually provides it — never to a hope. One of the four is not optional:

Dictate is mandatory. Ask and Imagine are not.

A valid caret/v1 backend takes speech. It must advertise "dictation": true; a backend with no working STT adapter is not a Caret backend and must never present itself as one. Ask and Imagine are each optional and are reported honestly off when nothing provides them. So a dictation-only backend (CARET_AGENT=off) is complete and valid — and a backend with a brilliant agent and no STT is not.

SurfaceRequired?Route
Dictation / STT Required Through the agent only if its adapter verifiably transcribes audio. No shipped preset does — Claude Code and Codex are text-only non-interactive CLIs, Hermes and OpenClaw expose no documented stable transcription contract, GrokBot exposes no verified non-interactive transcription interface, and the custom-http contract is text-JSON by definition. So speech is transcribed by the backend's own STT adapter — local OpenWhisper by default when installed, a hosted STT service via CARET_STT_HTTP_URL, or any command via CARET_STT_COMMAND — and only then does text reach the agent. No STT resolved is a hard stop: health reports "status": "not_ready" with the no_stt_adapter blocker, python3 -m caret_backend --check exits non-zero, and the connection QR refuses to generate.
Ask Optional Your selected agent, when you configure one. With CARET_AGENT=off — or auto with nothing installed — health reports "draft": false and /v1/draft answers 404 not_found rather than faking a reply. That is a valid backend, not a broken one.
Transcript cleanup Optional Your selected agent, as a constrained text-only cleanup request — fix the transcript, do not answer it, take no action. The CLI presets run in their read-only modes, so "no action tools" is enforced where the runtime can enforce it. With no agent, cleanup is off and dictation returns the raw transcript.
Imagine Optional Through the agent only if its adapter verifiably renders images. Exactly one shipped preset does: grokbot with CARET_GROKBOT_IMAGE=on, which serves Imagine from GrokBot's own image capability. Every other preset has no verified image-output interface, so Imagine uses the image provider you configure (CARET_IMAGE_COMMAND) and stays honestly off otherwise.

GET /v1/health reports the resolved route per surface in its routes block and the pass/fail verdict in its readiness block, so what the keyboard offers always matches what the backend can actually do: 

{"status": "not_ready",
 "capabilities": {"draft": true, "dictation": false, "imagine": false},
 "readiness": {"ready": false,
               "blockers": [{"code": "no_stt_adapter", "message": "…"}]}}

That shape — Ask on, Dictate off — is the one configuration this contract does not accept. It is shown here only so you recognise it as a failure.

Where the backend runs, and how Caret reaches it

The backend binds loopback and speaks plain HTTP; the keyboard requires https://. So every deployment is the same shape — backend on the machine where your agent lives, TLS in front — and the choice is only what provides the TLS.

ModeHowTrade-off
Local Mac, tailnet tailscale serve --bg 8787 gives the backend a private https://your-mac.your-tailnet.ts.net URL. Your iPhone joins the same tailnet. Recommended default. Nothing is exposed to the public internet; TLS certificates are handled for you; works away from home. Requires Tailscale on phone and Mac.
Private VPS / hosted box, tailnet Same as above, on the box where your agent runs. Same properties; the box needs no open ports at all.
VPS, public HTTPS A reverse proxy (Caddy shown in the runbooks) terminates TLS with an automatic Let's Encrypt certificate and forwards to 127.0.0.1:8787. Works from any network with no client software — but the endpoint is publicly reachable, so the bearer key and the proxy are your entire perimeter. Use a dedicated subdomain and keep the backend itself on loopback.
Not recommended

Port-forwarding your home router at the backend, or binding it to 0.0.0.0 without a proxy. The backend fronts an agent with an API key as the only lock; keep it off the open internet unless a proxy and a dedicated host are in front of it.

Pairing and the key model

Pairing is deliberately boring: a base URL and a bearer key, both entered once in Caret's settings — or scanned once, as a QR.

  1. Generate a key on the machine that runs the backend — python3 -c 'import secrets;print(secrets.token_urlsafe(32))'. Put it in CARET_API_KEYS. One key per device makes revocation a matter of deleting one string and restarting.
  2. Enter URL and key in Caret — by hand, or by scanning the connection QR below. The app calls GET /v1/health — the only anonymous endpoint — and shows you what it found: auth.valid tells "wrong key" apart from "wrong URL", and capabilities tells the keyboard exactly which surfaces this backend serves, so it never offers what the backend cannot do.
  3. Every other request is authenticated with Authorization: Bearer, compared in constant time. No keys configured means the backend fails closed: every request is 401 and health reports degraded.

The connection QR — caret-connect:v1

Typing a 43-character key into a phone is where most setups go wrong. So once the backend is configured and ready, it will render that same URL-and-key pair as a QR the Caret app scans: 

python3 -m caret_backend --qr --url https://your-mac.your-tailnet.ts.net

It prints the symbol in the terminal, plus a masked fingerprint of the payload — never the payload itself. Add --save ~/caret-connect.png to write a PNG instead (mode 0600), and --no-display to skip the terminal render entirely.

The QR is the credential.

It carries your API key, not a pointer to one. Anyone who scans it — or photographs it over your shoulder, or finds it in a screen recording — can use your backend until you rotate the key. So generation is opt-in and explicit (never a side effect of starting the server), the payload is never logged or printed in full, and a saved PNG is written owner-only. Treat it exactly as you would the key: show it to one phone, then delete the file. To revoke, change CARET_API_KEYS and restart — every QR ever generated dies with the old key.

The wire format

A compact JSON object, base64url-encoded without padding, behind a version prefix. Keys are sorted so two implementations produce the same bytes:

FieldMeaning
t Type. "agent" for a backend you run — the case here. ("hosted" exists for Caret's own service and must not carry a u: the client pins its own canonical URL, so a hosted code naming a URL is an attempt to aim a phone somewhere else, and is refused.)
u The backend's base URL, no trailing slash. Required for agent. https:// everywhere except loopback, RFC-1918 addresses and *.ts.net, where plaintext is allowed because the transport is already private.
k The API key, 10–300 characters, exactly as it appears in CARET_API_KEYS.

Worked example, pinned byte-for-byte on both sides — the key is fake:

{"k":"caret_demo_key_1234567890","t":"agent","u":"https://agent.example.com"}

caret-connect:v1:eyJrIjoiY2FyZXRfZGVtb19rZXlfMTIzNDU2Nzg5MCIsInQiOiJhZ2Vu
dCIsInUiOiJodHRwczovL2FnZW50LmV4YW1wbGUuY29tIn0

And the encoding as one shell line, if you would rather build the payload yourself. It reads the key from the environment so the key never lands in your shell history, and umask 077 plus a redirect keep the result off the terminal — its output is the credential: 

( umask 077; python3 -c 'import base64,json,os,sys;d={"k":os.environ["CARET_API_KEYS"].split(",")[0],"t":"agent","u":sys.argv[1].rstrip("/")};print("caret-connect:v1:"+base64.urlsafe_b64encode(json.dumps(d,separators=(",",":"),sort_keys=True).encode()).decode().rstrip("="))' https://your-mac.your-tailnet.ts.net > ~/caret-connect.txt )

Readiness gates the QR

--qr refuses while any readiness blocker stands. Handing a phone a code that connects to a backend with no microphone produces a keyboard that silently lacks its main feature and no explanation of why, so the CLI stops and names the blocker instead. --force exists for debugging and says so.

Pairing tokens — an optional server extension

The reference backend also implements short-lived, single-use pairing tokens (/v1/pairing/tokens, /v1/pairing/claim, /v1/pairing/revoke, and python3 -m caret_backend --pair): a five-minute secret bound to one server URL, exchanged over TLS for the durable key. The Caret app does not use this — it configures itself from a caret-connect:v1 code. The token flow is here for your own clients, shared machines, and any case where handing over a durable key as pixels is the wrong trade. It is documented in openapi.yaml and is not part of the caret/v1 client contract.

Security model

What the backend promises, and what stays your responsibility:

  • It never widens your agent's permissions. The CLI presets use each runtime's documented non-interactive, most-restricted mode — Claude Code in read-only plan mode, Codex in a read-only sandbox. The backend refuses to start if a configured command contains a known permission-bypass flag (--dangerously-skip-permissions, danger-full-access, …). It never enables tool actions, arbitrary shell execution, or background work on the agent's side.
  • A prompt is not a sandbox. The drafting and cleanup prompts tell the agent it is writing text, not acting — but for runtimes whose restriction flags are advisory (Hermes toolsets follow your profile), the runbook shows the documented way to narrow them, and recommends running the backend as a dedicated low-privilege user with its own agent profile. That recommendation is the default posture, not an extra.
  • Audio stays local by default. The default STT is OpenWhisper on the machine running the backend: recordings never leave it, and chunks are deleted as soon as a session produces its result. Configure a hosted STT and that trade-off is yours, explicitly.
  • No secret or content logging. Access logs carry method, path, status and request_id — never instructions, drafts, transcripts, near-cursor text, or keys. This is asserted by the test suite, not just promised.
  • What your agent sees per draft: the instruction you typed (or the local transcript of what you said), up to 4000 characters of text near the cursor (visible_text, often empty), and the host app's bundle id as a register hint. Near-cursor text is someone else's words — the framing treats it as untrusted context, never as a command.
  • Timeouts, not hangs. Every draft has a wall-clock budget (90 s default); overrun is a clean 504 draft_timeout, and a failed draft is never cached — retries can succeed.

Troubleshooting, from the outside in

SymptomMeaning
Startup fails with configuration error: … The message says exactly which variable to fix. --check reproduces it without serving.
Caret says it cannot reach the URL TLS layer. curl https://…/v1/health from the phone's network; if that fails, fix the proxy/tailnet before touching the backend.
Health shows "valid": false Key mismatch between the app and CARET_API_KEYS.
Health shows "status": "degraded" No keys configured; the backend is failing closed as designed. readiness.blockers says no_api_keys.
Health shows "status": "not_ready" No STT adapter resolved, so this is not yet a valid Caret backend — dictation is mandatory. Install OpenWhisper (brew install openai-whisper) or set CARET_STT_COMMAND / CARET_STT_HTTP_URL, then restart. readiness.blockers says no_stt_adapter.
No microphone in the keyboard Same cause: no STT resolved. routes.dictation in health says so, and the backend should not have been paired in this state.
--qr says NOT READY — refusing to hand out a connection Working as designed. Clear the named readiness blocker rather than reaching for --force.
Scanning the QR does nothing / the app rejects it Check the payload starts caret-connect:v1: and the URL in it is reachable from the phone. A key shorter than 10 characters is refused by both sides.
503 internal_error: … exited N The agent CLI failed; the stderr tail is in the message. Run the runbook's smoke command by hand as the backend's user.
504 draft_timeout The agent is slower than CARET_AGENT_TIMEOUT_S. Pin a faster model in the command, or raise the budget.

Every response carries a request_id; the backend logs one line per request with the same id, so a report from the keyboard gives you a grep target.
