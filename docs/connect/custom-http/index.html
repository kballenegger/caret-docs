connect · custom-http

A hosted agent behind your keyboard.

The generic fallback, for agents that are neither a local CLI nor one of the named presets: a service on a box you rent, an internal bot, anything you can put one HTTP endpoint in front of. The reference backend forwards each draft as a single JSON POST.

Looking for GrokBot?

GrokBot is a first-party backend with its own preset and its own runbook — connect/grokbot/ — not a custom-http deployment. It serves Ask and Imagine from its own model. Use this page only when no named preset fits.

Status: backend-supported

The backend's side of this contract — request shape, auth header, error mapping for unreachable/failing/malformed upstreams — is fully covered by the hermetic test suite. Your upstream is yours: this page defines exactly what it must do, and the smoke test in step 3 is the verification. No claim is made about any particular hosted agent product — and the contract is text-JSON by definition, so neither STT nor image generation routes through it.

The contract your endpoint implements

One request per draft. Deliberately as small as a contract can be:

POST <CARET_AGENT_HTTP_URL>
Content-Type: application/json
Authorization: Bearer <CARET_AGENT_HTTP_BEARER>     // only if you set one

{"prompt": "<the framed drafting prompt>"}

→ 200
{"text": "<the finished draft>"}
Your endpoint doesThe backend answers Caret
200 with a non-empty string text the draft, as normal
Any non-200 503 internal_error, retryable
Non-JSON body, or JSON without text 503 internal_error, retryable
Unreachable / times out 503 internal_error / 504 draft_timeout, retryable

The prompt arrives fully framed — instruction, optional near-cursor text, optional app hint, and the read-only "this is a draft, take no action" instruction. Transcript cleanup arrives through the same endpoint as a constrained text-only cleanup prompt. Your endpoint sends it to your agent and returns the reply. A five-line handler in any web framework is a complete implementation.

1 · Stand up the endpoint next to your agent

Wherever the agent lives — your VPS, a PaaS, a box on your LAN — add one route that receives {"prompt"}, calls the agent text-in, text-out, and returns {"text"}. Keep it as dumb as possible:

  • Do not give the route tool access, memory writes, or side effects — it is a drafting call, and the prompt says so.
  • Require the bearer token if the endpoint is reachable beyond loopback.
  • Do not log the prompt or the reply; log a request id and a status, the way the backend does.

2 · Configure the backend

Run the backend wherever you like — same box as the endpoint (then the URL is loopback and needs no TLS of its own) or your Mac pointing at the hosted endpoint over HTTPS: 

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

export CARET_AGENT=custom-http
export CARET_AGENT_HTTP_URL='https://agent.yourdomain.com/caret-draft'
export CARET_AGENT_HTTP_BEARER='…'           # whatever your endpoint checks
python3 -c 'import secrets;print(secrets.token_urlsafe(32))'  # generate a key — copy the output
export CARET_API_KEYS=paste-the-key-here                      # paste this into Caret later

python3 -m caret_backend --check
python3 -m caret_backend --port 8787

Two keys, two directions, on purpose: CARET_API_KEYS is what Caret presents to the backend; CARET_AGENT_HTTP_BEARER is what the backend presents to your endpoint. Neither is ever logged.

Dictation — mandatory, and not through this endpoint

STT never goes through the drafting endpoint — its contract is text-only. Dictation uses the backend's own STT lane: local OpenWhisper by default when installed on the machine running the backend, a hosted STT service via CARET_STT_HTTP_URL (one WAV POST → {"text"}), or any command via CARET_STT_COMMAND. See the STT section of the Connect overview.

Dictation is required: a backend with no working STT adapter reports "status": "not_ready" with the no_stt_adapter blocker, --check fails, and the connection QR refuses to generate. A hosted Ask endpoint with no STT is not a valid Caret backend, however well the drafts read.

3 · Smoke-test the whole chain

curl -s localhost:8787/v1/health | python3 -m json.tool
curl -s -X POST localhost:8787/v1/draft \
  -H "Authorization: Bearer $CARET_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

A draft here proves backend → endpoint → agent → back. This is the step that verifies your integration. Health's routes block shows how every surface resolved.

4 · Host modes and pairing

Backend on the hosted box: bind loopback, put the box's TLS in front — tailscale serve --bg 8787 for a tailnet-only URL, or a Caddy site block (reverse_proxy 127.0.0.1:8787) for public HTTPS. Backend on your Mac: point CARET_AGENT_HTTP_URL at the hosted endpoint over HTTPS and expose the backend to your phone with tailscale serve --bg 8787. Then pair as always: URL + key in Caret settings; the health check reports what actually resolved.

Or scan instead of typing, once --check passes:

python3 -m caret_backend --qr --url https://your-backend.example

That prints a caret-connect:v1 symbol carrying the base URL and the key; --save ~/caret-connect.png writes an owner-only PNG instead. It refuses while any readiness blocker stands. The code is the credential — anyone who scans it can use this backend until you rotate CARET_API_KEYS. Format and warnings: the connection QR.

Troubleshooting

SymptomFix
503 internal_error: upstream agent unreachable The backend cannot reach CARET_AGENT_HTTP_URL — curl it from the backend's machine.
503 internal_error: upstream agent answered HTTP 401/403 Your endpoint rejected the bearer — CARET_AGENT_HTTP_BEARER mismatch.
503 internal_error: upstream agent response has no "text" Your endpoint's response shape is off. It must be a JSON object with a non-empty string text.
504 draft_timeout The whole chain must answer inside CARET_AGENT_TIMEOUT_S (90 s default).

General transport and pairing problems are covered on the Connect overview.
