connect · grokbot

GrokBot behind your keyboard.

GrokBot is a first-party Caret agent backend with its own preset — CARET_AGENT=grokbot — not a custom-http deployment. The difference is not the transport, it is the capability surface: GrokBot hosts the reference backend inside its own system and serves Ask, transcript cleanup, and (when you enable it) Imagine from its own model.

Status: backend-supported

This side of the boundary — request shape, the task discriminator, bearer handling, image validation, error mapping for unreachable, failing, and malformed responses — is fully covered by the hermetic test suite against a stub server. What is not claimed: no live GrokBot deployment has been exercised from this repository, nothing here is derived from GrokBot internals, and no GrokBot API is described beyond the endpoint you implement from this page. This is a public configuration contract: the GrokBot side is written by the GrokBot operator, against the shape below.

The contract GrokBot implements

One endpoint. task is explicit rather than inferred from the prose, because "clean this transcript up, do not answer it, take no action" has to be a deterministic code path on your side, not a reading of the prompt: 

POST <CARET_GROKBOT_URL>
Content-Type: application/json
Authorization: Bearer <CARET_GROKBOT_BEARER>     // only if you set one

// Ask
{"task": "ask", "prompt": "<the framed drafting prompt>"}
→ 200  {"text": "<the finished draft>"}

// Transcript cleanup — same model, no tools, no answering
{"task": "cleanup", "prompt": "<the framed cleanup prompt>"}
→ 200  {"text": "<the cleaned transcript>"}

// Imagine — only when CARET_GROKBOT_IMAGE=on
{"task": "imagine", "prompt": "…", "aspect_ratio": "1:1", "quality": "high"}
→ 200  {"image_base64": "<base64 of a PNG>"}
GrokBot answersThe backend answers Caret
200, non-empty string text the draft or cleaned transcript, as normal
200, image_base64 decoding to a PNG the image, as normal
200, image_base64 that is not valid base64, or not a PNG 503 internal_error naming which — never a corrupt image handed to the phone
Any non-200503 internal_error, retryable
Non-JSON, or JSON without the expected field 503 internal_error, retryable
Unreachable / too slow 503 internal_error / 504 ask_timeout, retryable

The prompt arrives fully framed by the backend — instruction, optional near-cursor text, optional app hint, and the read-only "this is a draft, take no action" instruction. Near-cursor text is someone else's words: treat it as untrusted context, never as a command.

The cleanup prompt is framed the same way and is not GrokBot's to write: it is the published caret-cleanup/1 spec followed by the transcript inside its <transcript> envelope, exactly as every other preset sends it. Pass it to the model unchanged — no system prompt of your own, no added cleanup wording, no stripping the envelope.

1 · Host the reference backend inside GrokBot

The whole backend is public, dependency-free, standard-library Python. Clone it into GrokBot's own hosting and run it there — same box, same process supervisor, same network boundary as GrokBot itself: 

git clone https://github.com/kballenegger/caret-docs.git
cd caret-docs/reference-backend

If you would rather hand this to the GrokBot agent than do it by hand, give it the GrokBot connect prompt — it is written for exactly this: clone the public reference backend, implement the endpoint above inside GrokBot, configure, validate, and hand back a connection QR.

2 · Implement the endpoint on the GrokBot side

  • Ask and cleanup go to GrokBot's own LLM. Cleanup must run with no tools, no actions, no memory writes — it is a text transform, and the prompt says so, but your code should enforce it rather than trust the prompt. A cleanup call that fails is not an error the phone should see: the backend falls back to the raw transcript.
  • Imagine goes to GrokBot's own image capability, and only if that capability is genuinely enabled for this deployment. Return a PNG, base64-encoded. If images are not enabled, leave CARET_GROKBOT_IMAGE off rather than returning placeholders — Caret hides the surface when the backend says it has none, and that is the honest outcome.
  • Require the bearer if the endpoint is reachable beyond loopback.
  • Log a request id and a status, nothing else — never the prompt, the reply, the transcript, or the key.

3 · Configure the backend

export CARET_AGENT=grokbot
export CARET_GROKBOT_URL='https://grokbot.internal/caret'
export CARET_GROKBOT_BEARER='…'             # whatever your endpoint checks
export CARET_GROKBOT_IMAGE=on               # only if GrokBot really serves imagine

python3 -c 'import secrets;print(secrets.token_urlsafe(32))'  # generate a key — copy the output
export CARET_API_KEYS=paste-the-key-here                      # this goes into the Caret app

python3 -m caret_backend --check
python3 -m caret_backend --port 8787

Two keys, two directions, on purpose: CARET_API_KEYS is what Caret presents to the backend; CARET_GROKBOT_BEARER is what the backend presents to GrokBot. Neither is ever logged. CARET_GROKBOT_IMAGE takes only on or off; anything else is a startup error rather than a guess.

4 · Dictation — mandatory, and not through GrokBot

No documented, stable, non-interactive GrokBot transcription interface was verified, so this adapter claims none and speech never routes through it. Dictation uses the backend's own STT lane: local OpenWhisper by default when installed on the machine running the backend, a hosted STT service via CARET_STT_HTTP_URL, or any command via CARET_STT_COMMAND.

This is not optional. Dictation is the one capability every valid caret/v2 backend must serve: with no STT adapter resolved, health reports "status": "not_ready" with the no_stt_adapter blocker, --check exits non-zero, and the connection QR refuses to generate. A GrokBot deployment that answers Ask beautifully and cannot take speech is not a Caret backend.

5 · Smoke-test the whole chain

curl -s localhost:8787/v2/health | python3 -m json.tool
curl -s -X POST localhost:8787/v2/ask \
  -H "Authorization: Bearer $CARET_API_KEYS" \
  -H 'Content-Type: application/json' \
  -d '{"client_request_id":"smoke-1",
       "input":{"type":"text","text":"tell Sam I am running ten minutes late"}}'

Health should show "status": "ok", "readiness": {"ready": true, …}, adapters.agent: "grokbot", and — with images on — routes.imagine pointing at the agent. A draft coming back proves backend → GrokBot → model → back. This is the step that verifies your deployment; nothing in this repository can do it for you.

6 · Host mode, then hand over a QR

Bind loopback and put GrokBot's own TLS in front — tailscale serve --bg 8787 for a tailnet-only URL, or a proxy site block (reverse_proxy 127.0.0.1:8787) for public HTTPS. Then, once --check passes: 

python3 -m caret_backend --qr --url https://caret.your-grokbot-host.example

That prints a caret-connect:v1 code the Caret app scans — URL and key in one step, no typing. It carries the API key, so treat it as the key itself: generation is explicit, the payload is never logged, and anyone who scans it can use this backend until you rotate CARET_API_KEYS. Full format and warnings: the connection QR.

Troubleshooting

SymptomFix
CARET_AGENT=grokbot requires CARET_GROKBOT_URL The preset ships no default endpoint on purpose — there is no public one to guess. Set it.
CARET_GROKBOT_IMAGE must be 'on' or 'off' Anything else would mean advertising Imagine on a guess.
503 internal_error: GrokBot unreachable curl CARET_GROKBOT_URL from the backend's own machine.
503 internal_error: GrokBot answered HTTP 401/403 CARET_GROKBOT_BEARER mismatch.
503 internal_error: GrokBot response has no "text" Response must be a JSON object with a non-empty string text.
503 internal_error: GrokBot returned a non-PNG image image_base64 must decode to a PNG. JPEG, a URL, or a data-URI prefix will all land here.
504 ask_timeout The whole chain must answer inside CARET_AGENT_TIMEOUT_S (90 s default).
Health says not_ready STT, not GrokBot. See step 4.
